De-Para: o que mudou

Comparação lado a lado entre o estado inicial do repositório e o estado final após a execução.

Antes

Estado inicial do repositório — apenas o skill de orquestração, sem recursos auxiliares.

  • SKILL.md — definição do orquestrador (XML, fases, regras)
  • README.md — documentação pública
Depois

Estado final — três novos diretórios e o skill atualizado.

  • scripts/ — brave-search.sh · check-brave-credits.sh
  • prompts/ — ecc-prompts.md · ecc-skills.md · search-prompts.md
  • templates/ — html-explainer.html
  • SKILL.md — atualizado (ondas ilimitadas, novos recursos)
Antes: app sem configuração de pensadores

O usuário abria o app e não tinha como escolher quais modelos usar nos pensadores. O deep-think.ts usava um único modelo hardcoded (OPENAI_DEEPTHINK_MODEL), chamava fetch direto com process.env.OPENAI_API_KEY, e uma chave digitada na tela de setup nunca alcançava o loop de pensadores.

No Electron, o SetupScreen só pedia chave OpenAI. O backend não tinha rota para gravar chave em runtime. O catálogo de modelos da OpenRouter não era exposto ao frontend.

Depois: painel completo de configuração

O usuário clica em "Pensadores" na Sidebar e configura:

  • ModelSelect — combobox com busca sobre o catálogo da OpenRouter (400+ modelos), filtro de ano ≥ 2026, provedores filtráveis. Modelos já selecionados nunca somem da lista (parâmetro keep).
  • ThinkerRosterPanel — master, planner e 10 slots com toggle enabled, seleção de modelo+provedor, angle opcional por slot, effort. Warnings de provider sem chave renderizados por linha. Reset com um clique.
  • Chaves runtime — digitadas no SetupScreen (Electron) ou no card web, gravadas via PUT /api/provider-keys/:provider, alcançando o próximo request sem restart.
  • Roteamento multi-provedor — cada ModelChoice carrega provider+modelo; adapterFor(choice.provider) roteia para a URL/base correta com a chave certa. Modelos sem tools são chamados sem web search (degradação graciosa).

Impacto

O que cada mudança significa para quem usa o deep-orchestrator:

Busca Brave integrada — sub-agentes pesquisam na web direto do terminal (curl + API Brave), sem depender de outras ferramentas.
Créditos sob controle — o orquestrador consulta os créditos restantes da API antes de disparar ondas longas.
Execução confiável — contratos ECC (execução de código confiável) que os sub-agentes seguem ao executar código.
Busca padronizada — prompts de pesquisa consistentes entre sub-agentes (search-prompts.md).
De-para visível — toda execução termina com um EXPLAINER.html legível (este documento).
Processo documentado — ondas ilimitadas e o novo fluxo registrados no SKILL.md.

Premissas inferidas sem perguntar

O orquestrador opera em autonomia total: nenhuma pergunta foi feita ao usuário. Toda premissa assumida fica registrada aqui — para revisão e reprodutibilidade.

  • Filtro 2026+: MODEL_MIN_YEAR (default 2026) configurável por env, não literal fixo. Modelos sem data (DeepSeek inteira) incluídos por padrão (include_undated=true) — descartá-los esvaziaria a DeepSeek.
  • released_at na OpenRouter: created é data de ENTRADA NO CATÁLOGO, não de release. A UI escreve "descoberto em", nunca "lançado em".
  • OpenRouter sem autenticação: GET /api/v1/models responde 200 sem chave. O adapter omite o header Authorization quando não há chave — essencial para o fluxo "abrir o app sem chave e ver o catálogo".
  • keep cross-provider: O roster guarda ids puros (gpt-5.2-mini), o catálogo da OpenRouter prefixa (openai/gpt-5.2-mini). O keep normaliza: match no id completo OU no id sem prefixo de provedor.
  • Precedência runtime > ambiente: chave digitada na tela de setup é o sinal mais fresco, sem restart. O Electron persiste no settings store cifrado e reenvia via PUT no boot.
  • OPENAI_ADMIN_KEY separado: credits.ts tem dois escopos: OPENAI_API_KEY chama modelos, OPENAI_ADMIN_KEY lê custos. A chave digitada na tela NÃO habilita leitura de custos — assimetria preservada.
  • Card web não-bloqueante: o prompt de chaves é um card dispensável, não um portão como o SetupScreen do Electron. O smoke dev exige dashboard + headline do setup ausente.
  • POST /api/thinkers/reset: reset volta ao defaultRoster() — mesmo modelo de hoje, provider openai, 10 slots.
  • DeepSeek sem validação: sem endpoint documentado para validar chave; sem campo na UI. A chave é persistida e injetada, mas validada só no primeiro uso.
  • supports_tools: false: thinker chamado sem tools — responde na primeira volta, sem web search. Degradação projetada, não erro.
  • Warnings de provider: provider_key_missing emitidos para master, planner e slots HABILITADOS cujo provider não tem chave — antes do gasto.
